Technology

A stack, not an unfinished model.

Clouda OCR is built as five layers. Two are released, two are active, one is evidence-gated, and one is future. The model inside the pipeline is a replaceable component chosen by evidence — that is the architecture, not a limitation.

1 · Document runtime — released 2 · Evaluation — active 3 · Data — active 4 · Model integration — evidence-gated 5 · Hosted delivery — future

1 · Document runtime

Released

The released open-source runtime (v0.2.0, Apache-2.0) converts trusted born-digital PDF text into editable RTL-aware DOCX. Pages pass a canonical digital-text trust gate and are classified into explicit states — digital_text, blank_page, near_blank, pending_ocr_model, review_required — so scanned or uncertain pages are routed honestly instead of being passed off as OCR output.

View release View Project GitHub

2 · Evaluation

Active

Benchmarking, reproducibility and scoring. Frozen page manifests, stored per-model outputs, published Arabic normalization, deterministic decoding, and a canonical evaluator that recomputes every aggregate offline from stored outputs. This layer produced the published v0.1.0 benchmark and is running the current 462-page evaluation.

See the benchmark evidence

3 · Data

Active

Arabic document preparation, generation, degradation and provenance. Clean and degraded Arabic documents are produced deterministically from source text and seeds; sources are classified by license and permission into public, restricted and training-only handling. Storage priority follows data value: what is expensive to replace is preserved, what is deterministic is regenerable.

4 · Model integration / adaptation

Evidence-gated

The runtime uses a model-agnostic extraction interface and engine registry, so the OCR engine is a replaceable component. Which model gets integrated — and whether any adaptation or training happens at all — is decided by the completed evaluation: integration when an open model is strong enough; adaptation only if the evidence shows a meaningful gap that existing models do not close. No model architecture or training run is fixed yet.

5 · Hosted delivery

Future

A future stage. No hosted API, hosted service, or SaaS product exists today, and none is implied by the open-source release. Delivery models — self-hosted, managed, or partnership-based — are decisions for after the evaluation and integration layers mature.

Direction

Benchmark first. Adapt only when evidence demands.

The same discipline repeats at every layer: freeze the inputs, store the outputs, publish the method, and let results — not screenshots — drive the next decision. The model-agnostic architecture is what makes this honest: any engine can be measured, and any engine can be replaced.
