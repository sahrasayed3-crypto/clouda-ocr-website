Progress & Roadmap

From benchmark infrastructure to the first Arabic-specific adaptation.

The current phase is deliberately technical: benchmark, prepare data, select a base model, adapt it, evaluate, iterate.

Current state
177canonical distorted benchmark samples
~200 GBprepared Arabic document/PDF data
11 TB+known-size source material identified
v0.1.0public benchmark release

Benchmark foundation

  • Canonical sample manifest
  • Stored per-model outputs
  • Arabic-specific normalization and scoring
  • Public audit and reproducibility records

Data foundation

  • Working document generation/degradation pipeline
  • Prepared clean/degraded Arabic documents
  • Deterministic generation by seed
  • Different handling for public, restricted and training-only sources
Roadmap

The next milestones are measurable.

No Clouda model has been trained yet. The benchmark is being used to reduce model-selection risk before training resources are spent.

01Expand benchmark

Increase page count, document diversity, model coverage and hard failure cases.

02Scale preparation

Acquire and prepare additional Arabic source material and generated variants.

03First adaptation

Adapt the selected base model, evaluate on held-out data and iterate.

04Public model path

Release when quality, documentation and reproducibility are mature enough.

Storage strategy

Store what is expensive to replace. Regenerate what is deterministic.

Permanent storage is prioritized by data value rather than by raw volume.

Highest priority

Restricted/private data, prepared datasets that are expensive to reproduce, and hard-to-reacquire source material receive the strongest retention and backup policy.

Regenerable variants

Synthetic page images and distortions can be regenerated from source data and deterministic seeds, reducing long-term storage pressure.
