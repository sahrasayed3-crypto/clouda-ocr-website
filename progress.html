Progress

Execution status, stated like an engineering log.

What shipped, what is running, what the next decision is, and what comes later. The open-source runtime is released; the expanded evaluation is active; no production OCR model or hosted product exists yet.

Phase: Benchmarking & data preparation Software: v0.2.0 released Hosted product: Not released

Shipped

Done
  • Public open-source runtime — released as v0.2.0 (Apache-2.0): trusted born-digital PDF-to-DOCX conversion, page-level trust gate, honest routing states, RTL-aware output.
  • Published benchmark v0.1.0 — 177 distorted Arabic pages, 6 full-coverage models, released September 7, 2026 (Benchmark DOI: 10.5281/zenodo.22859930).
  • Reproducible evidence/archive — SHA-256 checksums, stored per-sample outputs, sanitization and license-review records, public methodology.
  • Data + evaluation infrastructure — deterministic, seed-based Arabic data generation and degradation; Arabic normalization and CER/WER scoring; provenance/licensing classification tooling.

Active

Running
  • 462-page frozen evaluation — in progress, currently paused pending additional compute capacity. Completed work is preserved and will not be recomputed.
  • 10-model evaluation plan — running against the frozen manifest under the same stored-outputs discipline as v0.1.0.
  • Dataset audit & preparation — multi-source Arabic OCR data foundation being curated and audited.
  • License/provenance classification — public, restricted and training-only sources handled separately.

Next decision

Evidence-gated
  • Choose the integration/adaptation path — decided from the completed 462-page evaluation, not from preference.
  • Train or adapt only if justified — a dedicated model is trained only if the evidence demonstrates a meaningful gap that existing open models do not close.
  • MVP if warranted — a first usable milestone built on validated results.

Later

Future
  • Hosted API / product — a future stage; no hosted service exists today.
  • Broader document-intelligence features — search, RAG-ready representations, and archive intelligence are downstream use cases after the OCR/document-conversion core is validated.
How status is kept honest. An evaluation on 462 held-out Arabic pages across multiple OCR/VLM candidates is in progress and currently paused pending additional compute capacity. Results will be published only after the evaluation is complete. Until then, the published v0.1.0 record remains the only published benchmark evidence.
Storage strategy

Store what is expensive to replace. Regenerate what is deterministic.

Permanent storage is prioritized by data value rather than by raw volume.

Highest priority

Restricted/private data, prepared datasets that are expensive to reproduce, and hard-to-reacquire source material receive the strongest retention and backup policy.

Regenerable variants

Synthetic page images and distortions can be regenerated from source data and deterministic seeds, reducing long-term storage pressure.
